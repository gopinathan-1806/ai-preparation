## Additional Study Details

### Core RAG architecture

Think of RAG as two stages: indexing and retrieval/generation. Indexing prepares knowledge; retrieval finds relevant context at query time; generation uses that context to produce an answer. A useful flow is Load → Split → Embed → Store → Retrieve → Rerank/Filter → Prompt → Generate.

### Self-RAG and Corrective RAG

Self-RAG focuses on evaluating or reflecting on retrieved information and/or generated responses. Corrective RAG focuses on assessing retrieval quality and taking corrective action when retrieved context is inadequate. The exact implementation varies by framework.

### Fusion RAG

Query rewriting or multi-query retrieval can generate multiple search formulations, retrieve results for each, and combine them. Reciprocal Rank Fusion (RRF) is one common way to merge rankings.

### BM25 + reranking

BM25 is a lexical retrieval/ranking approach that rewards useful term matches and term rarity. Hybrid retrieval can combine lexical and semantic retrieval, followed by reranking. This can improve retrieval for exact names, identifiers, and domain terminology.

### Temperature

Temperature changes the randomness of token selection. Lower values generally make outputs more deterministic; higher values generally increase variation. It is not a direct 'accuracy' control.

### Messages

Typical chat systems distinguish system instructions, user messages, and assistant/model messages. Tool-call messages may also appear in agentic workflows.

### Guardrails

Input guardrails can validate or block unsafe/unwanted requests before model execution. Output guardrails validate generated content before it is returned or acted upon. In tool-using agents, also protect the tool layer with authentication, authorization, validation, and least privilege.

### Evaluation

The 10,000+ runs and 95% threshold in the class notes are course guidance, not a universal production standard. Real evaluation should use a representative test set, clear metrics, failure analysis, and task-specific acceptance criteria such as retrieval quality, groundedness, correctness, safety, latency, and cost.

### Knowledge Graph RAG

A knowledge graph represents entities as nodes and relationships as edges. A graph-based retrieval approach can be useful when questions depend heavily on explicit relationships, multi-hop reasoning, or structured entity connections. It complements rather than simply replaces vector retrieval.

### RAG interview checklist

Be able to explain chunking, embeddings, vector similarity, metadata filtering, hybrid search, reranking, hallucination/grounding, evaluation, guardrails, latency, and cost.
